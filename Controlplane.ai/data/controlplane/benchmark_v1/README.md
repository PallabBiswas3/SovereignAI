# Benchmark v1 reviewer candidates

These files are generated by `scripts/build_benchmark_splits.py` from the
30-case synthetic development set.

- `development_candidates.jsonl`: 200 labelled candidates for development.
- `validation_candidates.jsonl`: 100 labelled candidates for threshold selection.
- `test_inputs_blinded.jsonl`: 400 inputs without labels for frozen evaluation.
- `reviewer_private/test_candidate_labels.jsonl`: local candidate labels, excluded
  from Git and intended only for independent review and adjudication.

All generated labels initially carry `annotation_status=candidate_unreviewed`.
They are regression/load-test material, not independent evidence of model quality.
Two reviewers should label every final test item independently. An adjudicator
must resolve disagreements before the labels are marked `gold_adjudicated`.

Each review JSONL row must include `id`, `reviewer_id`, `expected_action`,
`expected_categories`, `expected_subtypes`, and `gold_claims`. Validate completed
reviews with:

```bash
python scripts/validate_benchmark_reviews.py path/to/reviews.jsonl
```

The validator rejects items with fewer than two distinct reviewers and identifies
all disagreements requiring adjudication.

Do not reuse the same source document across train, validation, and final test in
the eventual real-data benchmark. Synthetic surface variants are not a substitute
for source-separated examples.
